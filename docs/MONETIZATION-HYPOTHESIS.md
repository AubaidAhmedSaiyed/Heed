# Monetization Hypothesis

## Potential Models

### 1. Per Agent
- **Why it might work**: Easy to understand. Aligns with "hiring" an AI employee.
- **Advantages**: Predictable revenue for customers.
- **Risks**: Customers might multiplex many workflows through one "agent" ID to save money.

### 2. Usage-Based (Per Action)
- **Why it might work**: True reflection of value. If HEED evaluates 1M actions, it provides more value than 100 actions.
- **Advantages**: Scales perfectly with the customer's success.
- **Risks**: Unpredictable billing for customers; might discourage them from routing low-risk actions through HEED.

### 3. Per Workspace / Seat
- **Why it might work**: Standard SaaS model.
- **Advantages**: Familiar to enterprise buyers.
- **Risks**: Agents do the work, not humans, so "seats" might be artificially low.

## Current Recommendation
A **Hybrid Model**: Free tier for local development. Paid tiers based on volume of actions evaluated + enterprise features (SSO, advanced connectors).
